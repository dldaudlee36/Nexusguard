이번 배포는 v3.1입니다. Agent는 3.0.0, Chrome 확장은 3.1.0입니다.
ChatGPT에서 감지한 기록은 확장 백그라운드에서 로컬 Agent로 전송합니다.
기존 확장 폴더를 업데이트했다면 chrome://extensions → GIGANG 새로고침(↻) → ChatGPT 탭 F5가 필요합니다.
Chrome 퍼즐 아이콘 → GIGANG Upload Detector를 누르면 Agent 연결 상태와 마지막 붙여넣기 저장 결과를 볼 수 있습니다.
저장 완료인데 대시보드에 없으면 수집 ON, IP 필터 전체, 이벤트 필터 PASTE_ATTEMPT를 확인하세요. 최신 100건 밖으로 밀려난 기록은 현재 API 조회에 보이지 않습니다.

# GIGANG v3 사용 방법

Windows 10/11 64비트용입니다. 실행 환경과 기존 Railway API 설정을 포함하여 Python을 따로 설치할 필요가 없습니다. 인터넷 연결은 필요합니다. ZIP을 새 폴더에 전체 압축 해제하세요.

## 누가 무엇을 실행하나요?

- 관리자: `start-dashboard.bat` — 팀원들의 서버 로그 확인.
- 사용자/팀원: `start-agent.bat` + 아래 Chrome 확장 — 자신의 PC 로그 전송.
- 둘 다: `start-all.bat`.
- 종료: 같은 폴더의 `stop-all.bat`. 브라우저 탭을 닫아도 프로그램은 계속 실행됩니다.

대시보드 주소: http://127.0.0.1:8501
이 주소는 각 PC에서 열리는 화면입니다. 로그는 모두 기존 Railway 중앙 서버에서 조회합니다. 관리자 PC의 사설 IP를 팀원에게 입력시키지 않습니다.

## Chrome 확장 설치·업데이트

1. 기존 Agent를 종료하고 이번 폴더의 Agent를 실행합니다.
2. Chrome 주소창에 `chrome://extensions`를 입력하고 개발자 모드를 켭니다.
3. 이전 폴더를 쓰는 GIGANG 확장을 제거하고, **압축해제된 확장 프로그램을 로드**에서 이번 폴더의 `browser_extension`을 선택합니다.
4. 확장 버전 **3.1.0**을 확인하고, 이미 열린 테스트 사이트를 새로고침합니다.
5. 일반 입력창에 테스트 문장을 붙여넣습니다. 암호 입력창은 제외합니다.

같은 확장 폴더의 파일을 교체한 경우에는 확장 카드의 새로고침 버튼과 사이트 새로고침을 모두 누르면 됩니다. 구버전과 새 버전을 동시에 등록하지 마세요.
Agent와 확장은 모두 v3로 맞춰야 붙여넣기가 서버까지 전달됩니다.

## 불러온 로그는 어디에서 보나요?

1. 기존 대시보드의 **중앙 서버 파이프라인**으로 이동합니다.
2. **Railway 실시간 수집 ON / OFF 스위치**를 켭니다.
3. 아래 **Railway 중앙 서버 수집 이벤트** 표를 확인합니다.
4. **이벤트 종류로 로그 골라 보기 → PASTE_ATTEMPT**를 선택하면 붙여넣기만 표시됩니다. **붙여넣기 글자 수** 열을 확인하세요.

수집 ON 동안 5초마다 서버 최신 100건을 조회합니다. `PC·IP별 수집 내역`과 IP 필터로 팀원 기록을 구분할 수 있습니다. 다른 네트워크에서는 내부 IP가 중복될 수 있습니다. 과거 unknown 기록은 그대로 남습니다.

| 이벤트 | 뜻 |
|---|---|
| WEB_ACCESS | Windows DNS 캐시에 새 도메인 흔적 발견. 광고·백그라운드 통신 포함 가능 |
| FILE_UPLOAD_ATTEMPT | Chrome의 파일 입력창에서 파일 선택·첨부 시도. 업로드 완료 확인은 아님 |
| PASTE_ATTEMPT | Chrome 웹페이지에서 텍스트 붙여넣기. 글자 수·사이트·시각과 PC 식별 정보만 저장 |

붙여넣은 본문·HTML·파일 내용은 전송하지 않습니다. 붙여넣기 자체를 유출 확정으로 처리하지 않습니다. Chrome 확장이 실행될 수 없는 브라우저 내부 페이지, 다른 앱, 일부 iframe은 감지 대상이 아닙니다. 파일 드래그앤드롭·이미지 붙여넣기는 이번 텍스트 감지 범위가 아닙니다.

Agent는 시작 시 기존 DNS 캐시를 기준으로 잡아 같은 사이트를 다시 열어도 접속 로그가 새로 생기지 않을 수 있습니다. 붙여넣기 테스트로 연결을 확인하세요.
원래 종합 관제·킬체인 분석·AI·IT 거버넌스 화면은 유지했습니다. 모의 시나리오도 있으므로 실제 수집 확인은 중앙 서버 표를 기준으로 합니다.

## 연결이 안 되면

- Agent 창에 **3.0.0**이 보이는지 확인합니다. `http://127.0.0.1:8765/health`에서도 버전을 확인할 수 있습니다.
- Chrome 확장 버전 3.1.0 확인 후 확장과 사이트를 모두 새로고침합니다.
- 사이트 개발자 도구 콘솔의 `Railway 저장 성공 PASTE_ATTEMPT`는 서버의 성공 응답을 받은 경우에만 표시됩니다. 전송 실패 메시지가 나오면 Agent 실행과 인터넷 연결을 확인하세요.
- 실패한 이벤트는 자동 재전송하지 않습니다. 연결을 복구한 뒤 새 테스트 문장을 붙여넣으세요.
- 대시보드가 안 열리면 `launcher-logs/dashboard-error.log`를 확인합니다. 8501/8765 포트 충돌은 이전 프로그램 종료 후 다시 실행합니다.
- 새 버전 실행 전에 이전 폴더의 `stop-all.bat`을 실행하세요. 이미 켜진 다른 버전 대시보드에 연결되지 않도록 합니다.

## 소스와 설정

- `dashboard/`: 팀원 최신 저장소에 붙여넣기 연동과 실행 오류 수정을 반영한 기존 대시보드.
- `source/agent/agent.py`: 이번 EXE를 만든 Agent 소스.
- `browser_extension/`: 이번 Chrome 확장.
- `source/railway_server/`: 기존 서버 소스 참고 사본. 운영 서버와 파일 단위 일치 여부는 확인하지 않았습니다.
- `dashboard/.env`: 기존 Railway 연결 키 포함.
- `runtime/`: Python 및 대시보드 의존성. 폴더 전체를 함께 전달하세요.

현재 운영 Railway에서 새 이벤트 저장과 재조회가 확인되어 이번 기능 때문에 서버를 다시 배포하거나 DB를 초기화할 필요는 없습니다. Gemini 원격 분석 키는 별도 설정입니다. 관리자·사용자는 실행 역할 설명이며 서버 접근 권한을 분리한 것은 아닙니다.
