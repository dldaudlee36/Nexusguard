## 1. 개발 배경 및 요구사항
- **문제점:** 기존 Streamlit Cloud에 배포된 애플리케이션의 콜드 스타트(Cold Start) 지연 시간(20~30초) 및 네트워크 레이턴시로 인해 사용자 경험이 저하되는 문제 발생.
- **사용자 요청:**
  - "너가 말한대로 streamlit을 통해 앱 형식으로 배포하긴 했는데 속도가 너무 느리다 vercel로 하면 좀 빨라지려나"
  - "둘 다 가능해? (Streamlit & Vercel 병행 배포)"

---

## 2. 기술적 접근 및 아키텍처 설계
1. **Stlite (Pyodide WebAssembly) 도입:**
   - 파이썬 서버 컨테이너를 상시 구동하는 대신, 클라이언트 웹 브라우저의 WebWorker 스레드에서 WebAssembly 기반으로 Python 런타임을 직접 기동.
   - 서버 대기 시간 0초, 페이지 로딩 즉시 로컬 메모리 상에서 초고속 실행.
2. **단일 번들러(`build_vercel_bundle.py`) 개발:**
   - `nexusguard` 패키지 내 14개 핵심 모듈과 의존성(`pydantic`, `pandas` 등)을 단일 HTML 파일 내 인라인 가상 파일시스템(FS)으로 패키징하는 자동화 빌더 구현.
   - Streamlit 공식 Stlite CDN 및 폰트, CSS 스타일시트를 최적화하여 묶음 배포.
3. **Vercel 정적 호스팅 라우팅 구성:**
   - `vercel.json`에 클라이언트 사이드 라우팅 및 정적 에셋 서빙 헤더 구성.

---

## 3. 주요 구현 내용
- `build_vercel_bundle.py`: 소스코드 파일들을 JSON 매핑 후 `@stlite/browser` 인라인 엔트리로 컴파일.
- `Nexusguard_Vercel/index.html`: 독립 실행 가능한 단일 WebAssembly 애플리케이션 생성 (약 136 KB).
- 이중 배포 파이프라인 수립: 로컬/Streamlit용(`Nexusguard_Git`)과 Vercel용(`Nexusguard_Vercel`)의 동시 지원.
